# Neon（Postgres）

## 1. プロジェクト

- リージョン: **AWS Asia Pacific (Singapore)**（Cloud Run の `asia-southeast1` と同じ地域）
- Postgres のバージョン: **18**（ローカルの `compose.yaml` と同じメジャーバージョン）
- データベース名: `chara_q`

## 2. ブランチの使い方

| ブランチ | 用途 |
|---|---|
| `main` | 本番。Cloud Run から接続する |
| `dev`（任意） | 本番のデータ移行のリハーサルなど、本番に近いデータで試すとき |
| 一時ブランチ | マイグレーションを本番に当てる前の確認。確認後に削除する |

- 普段の開発はローカルの Docker（`task db:up`）で行い、Neon のブランチは使わない。
- 使い終わったブランチは削除する（無料枠と費用の節約のため）。

## 3. 接続文字列

| 用途 | 接続文字列 |
|---|---|
| アプリ（Cloud Run） | **プール経由**（ホスト名に `-pooler` が付くもの） |
| マイグレーション | **直接接続**（`-pooler` が付かないもの） |

- どちらも `sslmode=require` を付ける。
- アプリ用の接続文字列は Secret Manager の `database-url` に登録する（[gcp.md](gcp.md)）。
  リポジトリや `.env.example` には書かない。
- プール経由（PgBouncer のトランザクションモード）で pgx のプリペアドステートメントが
  問題を起こす場合は、pgx の `default_query_exec_mode` を調整する。本番環境構築の Spec で確認する。

## 4. スケールトゥゼロ

- コンピュートの自動停止（scale to zero）は有効のままにする。最初の接続は数百 ms 遅くなる。
- API は起動時に DB への疎通確認を行うため、Cloud Run のコールドスタートと重なると
  起動に時間がかかることがある。問題になったら起動時の確認のタイムアウトを見直す。
