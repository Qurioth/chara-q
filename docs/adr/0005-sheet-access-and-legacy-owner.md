# ADR 0005: シートの公開範囲と、既存シートの所有者

- ステータス: 採用
- 日付: 2026-10-30

## 背景

シートには所有者を持たせる（constitution 原則 III）。そのため、誰がどの操作をできるかを
決める必要がある。

また、移行してくる既存のシートには所有者の情報がないため、その所有者も決める必要がある。

## 決定

### 公開範囲

| 操作 | できる人 |
|---|---|
| 一覧・検索・閲覧 | 誰でも（ログイン不要） |
| 複製 | ログインしたユーザー。複製したシートの所有者は、複製したユーザーになる |
| 作成 | ログインしたユーザー |
| 更新 | シートの所有者だけ |
| 削除 | シートの所有者だけ（2026-11-10 に追記。下の「後続の Spec で決めたこと」） |

### 既存シートの所有者

- システム管理者ユーザーを 1 人作り、移行する既存シートはすべてこのユーザーの所有にする。
  既存シートの修正は、管理者が行う。
- 本来の持ち主が後からユーザー登録した場合は、DB 操作で所有者を移す。
  持ち主かどうかの確認は、管理者がアプリの外で行う。

### 日時

- 既存シートの作成日時は、移行元のデータから復元する。
- 既存シートの更新日時は移行元にないため、作成日時と同じ値を入れる。

## 後続の Spec で決めること

- 管理者ユーザーの作り方とログイン方法（認証の Spec）
- 所有者を移す DB 操作の手順。手で SQL を打つと打ち間違えやすいため、決まった SQL を
  実行する Taskfile のタスクやコマンドにする案がある（認証またはデータ移行の Spec）
- シートの削除を許すか、許す場合は誰ができるか → 下の「後続の Spec で決めたこと」

## 後続の Spec で決めたこと

### シートの削除（[specs/003-character-sheet-base](../../specs/003-character-sheet-base/spec.md)、2026-11-10）

- 削除はシートの所有者だけができる。管理者も、自分が所有者でないシートは削除できない。
- 削除してもデータは消さず、削除した日時を記録する（論理削除）。削除したシートは一覧・検索・閲覧・
  更新・複製の対象から外れ、URL を開くと存在しないシートと同じ表示になる。
- 誤って削除したときは、所有者がアプリの外で管理者に連絡し、管理者が DB 操作で削除を取り消す。
  取り消しの操作は、アプリの画面・API・コマンドには用意しない。手順は
  [data-model.md の「削除の取り消し」](../../specs/003-character-sheet-base/data-model.md)。
- 削除したシートを一定の期間の後に完全に消す仕組みは、まだ持たない。

## 結果

- ログインしなくてもシートを探して見られる。
- 更新できるのはシートの所有者だけになる。
- 移行直後の既存シートは、本来の持ち主が所有者を移してもらうまで、自分では更新できない。
