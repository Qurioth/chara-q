# ADR 0004: UI ライブラリ（Tailwind CSS と shadcn/ui）

- ステータス: 採用
- 日付: 2026-10-30

## 背景

キャラクターシートは通常の Web ページと形が違う。たとえば、大きく表示するセレクトや、
サイコロ・フィクションの特技表（6 分野とギャップ A〜E の表）がある。

MUI のようなデザイン済みの部品ライブラリでは、こうした形に合わせるたびに、部品の内部の
クラス名を指定して見た目を上書きする必要がある（例: `'& .MuiSelect-select': { height: '100% !important' }`）。

ADR 0001 と constitution では、UI ライブラリを未決定事項にしていた。

## 決定

- **スタイルとレイアウトは Tailwind CSS（v4）で書く。**
  - シートの形（項目の配置、特技表のマス目など）は、Tailwind の CSS Grid・Flexbox で直接組む。
  - shadcn/ui の `Table` や `Card` をシートの枠組みには使わない。どちらも普通の Web ページ向けの
    見た目のため。
- **操作の伴う部品は shadcn/ui を使う。** 対象はセレクト、ダイアログ、ポップオーバー、トースト、
  タブ、チェックボックスなど。キーボード操作とフォーカス管理を自前で書かないため。
  - shadcn/ui はパッケージではなく、部品のソースを `apps/web` にコピーして自分のコードとして
    持つ。使う部品だけを追加する。
  - コピーした部品は、constitution の「生成コード」には当たらない。シートに合わせて
    `className` や部品のソースを直接変えてよい。
- **MUI は使わない。**
- **クリックで選ぶマス（特技表など）は `<button aria-pressed>` にする。** キーボードでも
  選べるようにするため。
- **システムごとの雰囲気は、テーマの CSS 変数とフォントで出す。** フォントは `next/font` で
  読み込む。たとえばゆうやけこやけでは Yuji Syuku と Mochiy Pop One を使う。

次は UI 基盤の Spec で決める。

- 導入する Tailwind CSS と shadcn/ui のバージョン、shadcn/ui の土台（Radix UI か Base UI か）
- 最初に入れる部品と、共通の入力部品（数値入力、ラベル付きテキストなど）の形
- フォームのライブラリ（react-hook-form など）
- テーマの CSS 変数とダークモードの切り替え方

これらの決定は [ADR 0007](0007-ui-foundation.md) に記録した。

## 検討した代案

- **MUI**: 部品がそろっている。ただし、シートの形に合わせるには `sx` で内部のクラス名を
  上書きする必要がある。また、Emotion はクライアントで動くため、Server Components と
  組み合わせるときに設定が増える。
- **Tailwind CSS だけを使う**: 依存は一番少ない。ただしセレクトやダイアログの
  キーボード操作やフォーカス管理を自前で書くことになり、アクセシビリティの不具合を作りやすい。

## 結果

- シートの見た目を、部品の内部のクラス名に頼らず Tailwind のクラスで直接書ける。
- shadcn/ui の部品はコピーなので、元のリポジトリで直った不具合は自動では入らない。
  使う部品を絞り、必要に応じて取り込み直す。
