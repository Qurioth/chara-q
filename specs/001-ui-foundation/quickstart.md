# Quickstart: UI 基盤の動作確認

実装が spec を満たすことを確かめる手順。自動テストで確かめる項目と、本物のブラウザで目視する項目
（clarify の回答: 本物のブラウザのテストは入れない）に分ける。

## 前提

```sh
mise install
task setup
```

API と DB は、部品確認ページの API 接続状態を見るときだけ必要（`task db:up`、`task db:migrate`、`task dev`）。
それ以外の確認は web だけで行える。

## 1. 自動テスト・静的チェック

```sh
task test:web          # web のテストだけ（API と DB は不要）
task test              # api と web のテスト（api のテストには task db:up が必要）
task lint              # ESLint と型チェック（Go を含む）
task check:generated   # 生成コードに差分がないこと
task build:web         # 本番ビルドが通ること
```

期待する結果:

- `task test:web` がすべて成功し、1 分以内に終わる（SC-008）。API と DB を止めた状態でも成功する（FR-034）。
- テストの一覧に、次の検証が含まれる（FR-037）。
  - 共通レイアウト: スキップリンク・ヘッダー・本文・フッターがあり、アプリ名のリンク先が `/`、フッターに
    `© 2026 Qurioth`、axe の違反が 0 件（SC-005）
  - トップページ: 紹介文と 2 つのシステムが表示され、「準備中」でリンクではない
  - テーマ: 保存値・端末の設定・不正な保存値・保存先が使えないときの表示中のテーマ、トグルで保存値と
    `<html>` のクラスが変わること、未選択のときだけ端末の設定の変化に追従すること、キーボードで押せること
  - 入力部品: [contracts/ui-components.md](contracts/ui-components.md) の属性（`for`、`aria-describedby`、
    `aria-invalid`、`aria-required`）、数値入力の決まり（[data-model.md](data-model.md)）、セレクトの
    キーボード操作、テキストエリアの改行、無効の状態、axe の違反が 0 件
  - ゲームシステム: `GameSystemScope` が `data-game-system` を付けること、`game-systems.ts` の `fonts` と
    `globals.css` の差し替えが一致すること
- わざと 1 件のテストを壊して `task test:web` を実行すると、失敗したテスト名が表示され、終了コードが 0 以外になる。

## 2. 本物のブラウザでの目視

`task dev:web` で web を起動し、ブラウザで開く。

### トップページ（`http://localhost:3000/`）

1. 開発者ツールで幅を 360px・768px・1280px・1920px に変え、横スクロールが出ず、ヘッダー・本文・フッターが
   すべて見えること（SC-001）。360px でヘッダーの要素が重ならないこと。
2. 本文が短くても、フッターが画面の下端にあること。
3. Tab キーを押すと最初に「本文へスキップ」が見え、Enter で本文に移ること（FR-006）。
4. タブのタイトルが `CharaQ` で、ヘッダーのアプリ名が Hina Mincho で表示されること。

### テーマ

1. `localStorage` の `chara-q-theme` を消し、端末（OS）の設定をダークにして開くと、ダークで表示されること。
2. 開いたまま OS の設定をライトに変えると、画面もライトになること（FR-015）。
3. トグルを押すとダークになり、再読み込みしても最初の描画からダークであること。開発者ツールの
   ネットワークで回線を遅くして（Slow 4G など）再読み込みしても、ライトが一瞬も見えないこと（FR-014、SC-002）。
   10 回繰り返す。
4. その状態で OS の設定を変えても、画面はダークのままであること。
5. 開発者ツールで JavaScript を無効にして開くと、OS の設定に合わせた色で読めること。

### 部品確認ページ（`http://localhost:3000/dev/ui`）

1. 4 つの入力部品の各状態が、ライト・ダークの両方で見分けられること。開発者ツールのコントラストの表示で、
   本文の文字・ラベル・補足説明・エラー文言・プレースホルダーが 4.5:1 以上であること（SC-004）。
2. マウスを使わず、Tab と矢印キーと Enter だけで、すべての部品に値を入れ、セレクトを選び、テーマを
   切り替えられること。フォーカスの輪郭がどの部品でも見えること（SC-003）。
3. ゆうやけこやけの領域の見出しが Mochiy Pop P One、筆文字が Yuji Syuku、ビギニングアイドルの領域の見出しが
   Mochiy Pop P One、領域の外は端末のゴシック体で表示されること。
4. 開発者ツールのネットワークでフォントのファイル（`next/font` が自前で配信する `/_next/static/media/*.woff2`）の
   読み込みを止めて再読み込みしても、文字が代替フォントですぐ表示されること（SC-007）。
5. トップページを開いたとき（部品確認ページを開く前、キャッシュを消した状態）に、システム用のフォントが
   ダウンロードされていないこと（FR-022）。
6. API を起動していれば、API の接続状態が表示されること。

### 本番ビルド

```sh
task build:web
pnpm --filter @chara-q/web start
```

1. `http://localhost:3000/dev/ui` が 404 であること（FR-032）。
2. トップページを開発者ツールの Lighthouse（モバイル）で計測し、LCP が 2.5 秒以内であること（SC-006）。
