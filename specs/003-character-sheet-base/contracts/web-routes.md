# Contract: 画面、URL、ヘッダー（`apps/web`）

設計の理由は [research.md](../research.md) の R13〜R16。

## 画面

| URL | ログイン | この機能で作るか | 内容 |
|---|---|---|---|
| `/sheets` | 不要 | 作る | 一覧と検索（下の「一覧の URL のクエリ」） |
| `/sheets/<ID>` | 不要 | 作る | 閲覧画面の共通部分。見つからなければ「シートが見つかりません」 |
| `/sheets/<ID>/edit` | 所有者 | 作らない | 編集。各システムの Spec で作る |
| `/sheets/new/<システム>` | 必要 | 作らない | 作成（`<システム>` は `yuyakekoyake`・`beginning-idol`）。各システムの Spec で作る |

- 作らない URL は、この機能ではページがないため、Next.js の既定の「見つからない」になる。
- `<ID>` は UUID。大文字が混ざっていても、api が同じシートとして扱う。

## 一覧の URL のクエリ

| キー | 値 | 既定 | 知らない値・形の正しくない値 |
|---|---|---|---|
| `system` | `yuyakekoyake`・`beginning-idol` | なし（すべて） | なし（すべて）として扱う |
| `q` | キーワード（前後の空白は無視） | なし | — |
| `mine` | `1` | なし | `1` 以外はなしとして扱う。ログインしていなければ無視する |
| `sort` | `updated`・`updated-asc`・`created`・`created-asc`・`name`・`name-desc` | `updated` | `updated` として扱う |
| `page` | 1 以上の整数 | `1` | 1 として扱う。大きすぎる値は api が最後のページに丸める |

- 既定の値は URL に含めない（例: すべての既定なら `/sheets`）。
- 同じキーが複数あるときは、最初の値を使う。
- 検索のフォームを送信すると `page` はなくなり、最初のページに戻る。

## 一覧の画面

- 見出し「キャラクターシート一覧」。
- 検索のフォーム（GET、`action="/sheets"`。JavaScript が動くときは `sheetSearchHref` の URL へ移動する、research R14）:
  - キーワード（テキスト入力、ラベル「キーワード」、補足「キャラクター名・プレイヤー名」）
  - システム（`SelectField`、「すべて」・ゆうやけこやけ・ビギニングアイドル）
  - 並び順（`SelectField`、「更新日時の新しい順」・「更新日時の古い順」・「作成日時の新しい順」・
    「作成日時の古い順」・「キャラクター名の順」・「キャラクター名の逆の順」）
  - 自分のシートだけ（チェックボックス。ログインしているときだけ表示）
  - 「検索」のボタン。条件があるときは「条件を外す」（`/sheets` へのリンク）
- 件数（「全 N 件」）。
- 一覧の各行: キャラクター名（閲覧画面へのリンク）・プレイヤー名・システム・所有者の表示名・
  更新日時。幅の狭い画面では、行を縦に積んだカードの形にし、横スクロールを出さない。
- 表の見出しでの並び替え（research R14）:
  - 「キャラクター名」と「更新日時」の見出しは、並び順を変えた一覧へのリンク（`page` なし、
    ほかの条件は保つ）。並んでいない列は最初の向き（`name`・`updated`）、並んでいる列は逆の向き。
  - 並んでいる列の `<th>` に `aria-sort`（`ascending`・`descending`）と、向きの矢印。
    並んでいない列には上下の矢印を薄く表示する。
  - リンクには、選んだときの並び順を視覚的に隠した文で添える（例: 「更新日時の古い順に並べ替える」）。
  - 作成日時の並び順で表示しているときは、どちらの見出しにも `aria-sort` を付けない。
- 0 件のとき: 「条件に合うシートはありません」と「条件を外す」。シートが 1 件もないときは
  「まだシートはありません」。
- ページ送り: 「前へ」「次へ」とページ番号のリンク。現在のページは `aria-current="page"`。
  ページが多いときは、最初・最後・現在の前後 2 ページを表示し、間を「…」にする。1 ページだけの
  ときは表示しない。

## 閲覧の画面

- 見出しはキャラクター名。その下にシステムの名前、所有者の表示名、作成日時・更新日時。
- 共通の項目: プレイヤー名・年齢・性別・メモ（メモは改行を保つ）。空の項目は「未入力」と表示する。
- システム固有の部分の場所（`lib/sheets/system-views.ts` の部品）。この機能では
  「このシステムの項目は準備中です」。
- 所有者の操作の場所。この機能では何も置かない（各システムの Spec が編集・複製・削除を置く）。
- 題名: `<キャラクター名> | CharaQ`。
- 見つからないとき（`not-found.tsx`）: 「シートが見つかりません」と、一覧へのリンク。存在しない・
  削除された・形の正しくない ID で同じ表示にする（FR-018）。
- 日時はすべて `Asia/Tokyo` の `YYYY/MM/DD HH:mm`。

## ヘッダー

- 右側の操作の領域は「テーマの切り替え・シート一覧・アカウント（ログイン）」の順に並べる。アイコンだけの
  テーマの切り替えを、アイコンと文字の付いた操作の間に挟まない。
- 「シート一覧」（`/sheets` へのリンク）の見た目は「ログイン」と同じ。`sm` 未満ではアイコンだけにし、
  `aria-label="シート一覧"` を付ける。
- `/sheets` 以下を表示しているときは `aria-current="page"`。
- 幅 360px で、ロゴ・リンク・テーマの切り替え・アカウントのメニューが重ならない。

## Server Components 用の関数（`lib/api/server.ts`、`server-only`）

| 関数 | 内容 |
|---|---|
| `queryWithSession`（既存） | セッションの Cookie がなければ api を呼ばずに `null` |
| `queryApi`（新規） | セッションの Cookie があれば付け、なければ付けずに api を呼ぶ。`cache: "no-store"` |

- 一覧と閲覧は `queryApi` を使う。閲覧の本体と `generateMetadata` は、React の `cache()` で包んだ
  `getCharacterSheet(id)` を共有し、api の呼び出しを 1 回にする。
