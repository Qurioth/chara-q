# Feature Specification: キャラクターシートの共通基盤

**Feature Branch**: `003-character-sheet-base`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "キャラクターシートの共通基盤: 全システム共通のシートの型・保存・一覧・検索・閲覧・作成・更新を用意する。constitution III と ADR 0005 に従う。（GraphQL では interface CharacterSheet に共通の項目を置き、システムごとの型がこれを実装する。システム固有の部分は JSON で返す。DB では、所有者・システム・キャラクター名・更新日時などを列にし、シート本体を JSONB に保存する。一覧・検索・閲覧はログインなしでできる。作成と複製はログインしたユーザー、更新は所有者だけができる。関連データ（所有者の表示名など）は DataLoader で解決する。含めないもの: 各システムの項目と画面（ゆうやけこやけ・ビギニングアイドルの Spec で扱う）、画像、ココフォリア出力、既存データの移行。clarify で決めること: 共通の項目、一覧と検索の条件と並び順、ページの送り方、複製と削除を含めるか、シートの URL、システムがない段階で画面をどこまで作るか）"

## Clarifications

### Session 2026-11-10

- Q: 全システム共通のシートの項目を、どの組み合わせにするか？ → A: キャラクター名・プレイヤー名・年齢・性別・メモの 5 項目。ビギニングアイドルでは性別を空のままにできる。上限はキャラクター名 100・プレイヤー名 50・年齢と性別 20・メモ 10,000 文字。
- Q: シートの一覧の絞り込み・並び順・ページの送り方を、どの組み合わせにするか？ → A: 絞り込みはシステム・キーワード（キャラクター名・プレイヤー名の部分一致）・「自分のシートだけ」（ログイン時）。並び順は更新日時・作成日時・キャラクター名で切り替えられ、既定は更新日時の新しい順。ページ番号で 20 件ずつ送る。
- Q: シートの複製と削除を、この機能に含めるか？ → A: 両方含める。削除は所有者だけができ、一覧・閲覧から消えるが DB には残す。誤って消したときは、管理者が DB 操作で戻す。
- Q: シートの画面の URL を、全システム共通の形にするか、システムごとの形にするか？ → A: 共通の URL。一覧 `/sheets`、閲覧 `/sheets/<ID>`、編集 `/sheets/<ID>/edit`、作成 `/sheets/new/<システム>`。
- Q: システム固有の項目がまだないこの機能で、シートの画面をどこまで作るか？ → A: 一覧（検索を含む）と閲覧画面の共通部分だけ。作成・更新・複製・削除はこの機能では API だけで用意し、画面は各システムの Spec で作る。

### Session 2026-11-11

- Q: 一覧の並び順に逆の順を加え、表の見出しでも並び替えられるようにするか？ → A: 加える。更新日時・作成日時・キャラクター名のそれぞれに順と逆の順を用意し、検索のフォームのプルダウンで 6 つから選べる。表の形の一覧では、キャラクター名と更新日時の見出しを選ぶと並び替わり、同じ見出しをもう一度選ぶと逆の向きになる。カードの形（幅の狭い画面）には見出しがなく、作成日時は列にないため、プルダウンは残す。

## User Scenarios & Testing *(mandatory)*

この機能は、各システムの Spec（ゆうやけこやけ・ビギニングアイドル）が共通して使う土台を作る。
画面は一覧（検索を含む）と閲覧画面の共通部分だけを作る。作成・更新・複製・削除は API だけを
用意して API で確かめ、その画面は各システムの Spec が作る。

### User Story 1 - ログインせずにシートを探す (Priority: P1)

訪問者は、ログインせずにシートの一覧を開き、システムやキーワードで絞り込み、並び順を変えて、
目当てのシートを探す。ログインしたユーザーは、自分のシートだけに絞り込める。一覧の各行には、
キャラクター名・プレイヤー名・システム・所有者の表示名・更新日時が表示される。件数が多いときは
ページを送って続きを見る。検索の条件・並び順・ページは URL に含まれ、URL を共有すれば同じ結果を
開ける。

**Why this priority**: セッションの参加者がキャラクターを見つける入口であり、ADR 0005 の
「誰でも探して見られる」という決定の中心になる。各システムの Spec も、この一覧を前提にする。

**Independent Test**: システム・キャラクター名・プレイヤー名・所有者・日時の異なるシートを DB に
用意し、ログインしていない状態とログインした状態で一覧を開く。絞り込み・並び順・ページ送り・
URL の共有を確かめる。

**Acceptance Scenarios**:

1. **Given** ログインしていない, **When** シートの一覧を開く, **Then** 削除されていないすべてのシートが更新日時の新しい順に表示され、各行にキャラクター名・プレイヤー名・システム・所有者の表示名・更新日時が表示される
2. **Given** 複数のシステムのシート, **When** システムで絞り込む, **Then** そのシステムのシートだけが表示される
3. **Given** シート, **When** キーワードで検索する, **Then** キャラクター名またはプレイヤー名にキーワードを含むシートだけが表示される。英字の大文字と小文字、全角と半角の違いは区別しない
4. **Given** ログインしている, **When** 「自分のシートだけ」で絞り込む, **Then** 自分が所有者のシートだけが表示される。システムとキーワードの絞り込みと組み合わせられる
5. **Given** ログインしていない, **When** 一覧を見る, **Then** 「自分のシートだけ」の絞り込みは表示されない
6. **Given** シート, **When** 並び順を作成日時・キャラクター名、またはそれぞれの逆の順に切り替える, **Then** 選んだ順に並ぶ（例: 作成日時の古い順、キャラクター名の逆の順）。絞り込みの条件は保たれ、最初のページに戻る
   - 表の形の一覧で、並んでいない列の見出し（キャラクター名・更新日時）を選ぶとその列の最初の向きに、並んでいる列の見出しを選ぶと逆の向きに並び替わる
7. **Given** 1 ページの件数（20 件）より多いシート, **When** 次のページ・ページ番号を選ぶ, **Then** そのページのシートが、前後のページと重複も抜けもなく表示される。全体の件数またはページ数がわかる
8. **Given** 検索の条件・並び順・ページを指定した一覧, **When** その URL を別のブラウザで開く, **Then** 同じ条件・同じ並び順・同じページの結果が表示される
9. **Given** 条件に合うシートがない, **When** 検索する, **Then** 該当するシートがないことと、条件を外す操作が表示される
10. **Given** 一覧の行, **When** 行を選ぶ, **Then** そのシートの閲覧画面（`/sheets/<ID>`）に移動する
11. **Given** 任意の画面, **When** ヘッダーを見る, **Then** シートの一覧への入口がある

### User Story 2 - ログインせずにシートを見る (Priority: P1)

訪問者は、シートの URL（`/sheets/<ID>`）を開いて、ログインせずにシートを見る。共通の項目
（キャラクター名・プレイヤー名・年齢・性別・メモ）、システム、所有者の表示名、作成日時と更新日時が
表示される。システム固有の部分は、そのシステムの Spec が表示する。

**Why this priority**: TRPG のセッションでは、キャラクターシートの URL を共有して他の参加者に
見せるのが主な使い方になる。一覧（US1）からも、共有された URL からも、ここにたどり着く。

**Independent Test**: シートを DB に用意し、ログインしていない状態でその URL を開く。共通の項目と
所有者の表示名が表示され、所有者のログイン ID はどこにも含まれないことを確かめる。

**Acceptance Scenarios**:

1. **Given** ログインしていない, **When** シートの URL を開く, **Then** 共通の項目・システム・所有者の表示名・作成日時・更新日時が表示される
2. **Given** 存在しないシート・削除されたシート・形の正しくない ID の URL, **When** 開く, **Then** どの場合も同じように、シートが見つからないことと、一覧への移動の操作が表示される
3. **Given** シートの閲覧画面, **When** 画面と API の応答を見る, **Then** 所有者のログイン ID は含まれず、表示名だけが含まれる
4. **Given** 所有者が無効にされたシート, **When** 開く, **Then** 無効にされる前と同じように表示される
5. **Given** シートの閲覧画面, **When** ブラウザのタブの題名を見る, **Then** キャラクター名とアプリ名が含まれる
6. **Given** 性別などの共通の項目が空のシート, **When** 開く, **Then** 空の項目は未入力とわかる形で表示され、画面が崩れない

---

### User Story 3 - ログインしてシートを作る (Priority: P1)

ログインしたユーザーは、システムを選んで新しいシートを作る。作ったシートの所有者は、作った
ユーザーになる。作ったシートは、すぐに一覧と閲覧画面に表示される。この機能では API だけを用意し、
作成画面（`/sheets/new/<システム>`）は各システムの Spec で作る。

**Why this priority**: シートがなければ一覧も閲覧も意味がない。各システムの Spec は、この作成の
仕組みにシステム固有の項目と画面を載せる。

**Independent Test**: ログインしたユーザーで API からシートを作り、一覧と閲覧画面に表示されること、
所有者が自分になっていることを確かめる。ログインしていない状態では作れないことを確かめる。

**Acceptance Scenarios**:

1. **Given** ログインしている, **When** システムと共通の項目とシステム固有の部分を指定してシートを作る, **Then** 自分が所有者のシートができ、作成日時と更新日時が作った時刻になり、一覧の先頭に表示される
2. **Given** ログインしていない, **When** シートを作る操作を API に送る, **Then** シートは作られず、ログインが必要であることが返る
3. **Given** ログインしている, **When** キャラクター名を空にする・項目の長さの上限を超える・存在しないシステムを指定する, **Then** シートは作られず、どの項目をどう直せばよいかが返る

---

### User Story 4 - 所有者がシートを更新する (Priority: P1)

シートの所有者は、自分のシートの共通の項目とシステム固有の部分を変えて保存する。保存すると
更新日時が新しくなり、一覧の上の方に移る。所有者以外は、どの手段でも更新できない。この機能では
API だけを用意し、編集画面（`/sheets/<ID>/edit`）は各システムの Spec で作る。

**Why this priority**: セッションのたびにキャラクターは成長し、シートを書き換える。ADR 0005 と
constitution の「更新は所有者だけ」を、API の段階で確実に守る必要がある。

**Independent Test**: 2 人のユーザーを用意し、所有者が API で更新できること、もう 1 人と
ログインしていない訪問者は更新できないことを確かめる。

**Acceptance Scenarios**:

1. **Given** シートの所有者としてログインしている, **When** 共通の項目とシステム固有の部分を変えて保存する, **Then** 内容が変わり、更新日時が保存した時刻になる。作成日時・所有者・システムは変わらない
2. **Given** 所有者でないユーザー（管理者を含む）・ログインしていない訪問者, **When** 更新の操作を API に送る, **Then** シートは変わらず、更新できないことが返る
3. **Given** 所有者が同じシートを 2 か所で読み込んでいる, **When** 片方で保存した後に、もう片方で古い内容をもとに保存する, **Then** 後の保存は受け付けられず、他の場所で更新されたことが返る。先の保存の内容は失われない
4. **Given** シートの所有者, **When** システムを変えて保存しようとする, **Then** システムは変えられない
5. **Given** 削除されたシート, **When** 所有者が更新しようとする, **Then** 更新できず、シートが見つからないことが返る

---

### User Story 5 - 他の人のシートを複製して自分のものにする (Priority: P2)

ログインしたユーザーは、気に入ったシートや、所有者から引き継ぎたいシートを複製する。複製した
シートの所有者は複製したユーザーになり、元のシートとは別のシートとして更新できる。この機能では
API だけを用意し、複製の操作の画面は各システムの Spec で作る。

**Why this priority**: ADR 0005 で操作として定めているが、作成（US3）と更新（US4）があれば
代わりに手で写せるため P2 とする。

**Independent Test**: ユーザー A のシートをユーザー B が API で複製し、複製が B の所有になること、
複製を更新しても元のシートが変わらないことを確かめる。

**Acceptance Scenarios**:

1. **Given** ログインしている, **When** 他のユーザーのシートを複製する, **Then** 同じシステム・同じ内容で、自分が所有者の新しいシートができる。キャラクター名の末尾には複製であることがわかる文字が付き、作成日時と更新日時は複製した時刻になる
2. **Given** 複製したシート, **When** 複製を更新・削除する, **Then** 元のシートは変わらない。元のシートが後で更新・削除されても、複製は変わらない
3. **Given** ログインしている, **When** 自分のシートを複製する, **Then** 他の人のシートと同じように複製できる
4. **Given** ログインしていない, **When** 複製の操作を API に送る, **Then** 複製されず、ログインが必要であることが返る
5. **Given** 削除されたシート, **When** 複製しようとする, **Then** 複製できず、シートが見つからないことが返る

---

### User Story 6 - 所有者がシートを削除する (Priority: P2)

シートの所有者は、要らなくなった自分のシートを削除する。削除したシートは一覧と閲覧画面から
消え、URL を開いても見つからない表示になる。データは消さずに残し、誤って削除したときは、
所有者がアプリの外で管理者に連絡し、管理者が DB 操作で戻す。この機能では API だけを用意し、
削除の操作の画面（確認を含む）は各システムの Spec で作る。

**Why this priority**: 試しに作ったシートや不要になったシートが一覧に残り続けると探しにくく
なるが、作成・更新・閲覧（P1）がなくても困らないため P2 とする。

**Independent Test**: 所有者が API でシートを削除し、一覧・閲覧・更新・複製の対象から外れること、
DB にはデータが残っていることを確かめる。所有者以外は削除できないことを確かめる。

**Acceptance Scenarios**:

1. **Given** シートの所有者としてログインしている, **When** 自分のシートを削除する, **Then** そのシートは一覧と検索に表示されなくなり、URL を開くと存在しないシートと同じ表示になる
2. **Given** 所有者でないユーザー（管理者を含む）・ログインしていない訪問者, **When** 削除の操作を API に送る, **Then** シートは削除されず、削除できないことが返る
3. **Given** 削除したシート, **When** 管理者が DB を見る, **Then** シートの内容と削除した日時が残っている
4. **Given** 削除したシート, **When** 管理者が DB 操作で削除を取り消す, **Then** シートは削除前と同じ内容・同じ URL で、一覧と閲覧画面に戻る
5. **Given** 既に削除したシート, **When** もう一度削除する, **Then** シートが見つからないことが返る

---

### Edge Cases

- キャラクター名・プレイヤー名・年齢・性別の前後の空白は取り除いて保存する。空白だけの
  キャラクター名は空として扱う。メモの改行は保つ。
- キャラクター名・プレイヤー名・年齢・性別に改行などの制御文字が含まれるときは、受け付けない。
  日本語・絵文字は受け付ける。
- 同じキャラクター名のシートが複数あってもよい。
- 検索のキーワードの前後の空白は無視する。空のキーワードは条件なしとして扱う。キーワードに `%` や
  `_` などの記号が含まれても、記号として文字どおりに検索する。
- 存在しないページ番号・負のページ番号・数値でないページ番号を URL で指定したときは、エラーに
  せず、範囲内の最も近いページ（または最初のページ）を表示する。
- 存在しないシステム・存在しない並び順を URL に指定したときは、エラーにせず、それぞれ絞り込み
  なし・既定の並び順（更新日時の新しい順）として扱う。
- 「自分のシートだけ」を含む URL をログインしていない状態で開いたときは、エラーにせず、その条件を
  外した一覧を表示する。その URL を別のユーザーが開いたときは、開いたユーザー自身のシートが
  表示される。
- 一覧を見ている間に他の人がシートを更新・削除して並び順が変わっても、ページを送ったときに
  エラーにはならない。
- 並び順の項目（更新日時・作成日時・キャラクター名）が同じシートが複数あっても、並び順は毎回
  同じになる。
- シートの所有者が無効にされても、シートは一覧・閲覧に表示し続ける。所有者は無効の間は更新・
  削除できない（ログインできないため）。
- システム固有の部分として、JSON のオブジェクト以外（配列・文字列・null など）や、大きすぎる値が
  送られたときは、受け付けない。中身の項目の検証は、各システムの Spec で加える。
- 閲覧画面と一覧に表示する文字列（キャラクター名・メモなど）は、HTML として解釈せず、文字として
  表示する。
- ログインが切れた状態（他のブラウザでログアウトした・無効にされたなど）で作成・更新・複製・
  削除を送ったときは、何も変えずにログインが必要であることを返す。
- 管理者も、自分が所有者でないシートは更新・削除できない。移行した既存シート（管理者の所有）は、
  管理者が所有者として更新できる（ADR 0005）。
- 作成・編集の画面の URL（`/sheets/new/<システム>`、`/sheets/<ID>/edit`）は、この機能では作らない。
  開いたときは、存在しない画面として扱う。

## Requirements *(mandatory)*

### Functional Requirements

#### シートの型と保存（constitution III）

- **FR-001**: すべてのシートは、全システム共通の項目として、キャラクター名・プレイヤー名・年齢・性別・メモを持たなければならない（MUST）。キャラクター名以外は空でもよい（ビギニングアイドルなど、性別を使わないシステムでは空のままにする）。
- **FR-002**: すべてのシートは、ID・システム・所有者・作成日時・更新日時を持たなければならない（MUST）。ID はシートの作成時に決まり、推測しにくい値にする（MUST）。
- **FR-003**: API では、共通の項目と FR-002 の項目を `interface CharacterSheet` に置き、ゆうやけこやけとビギニングアイドルのそれぞれの型がこれを実装しなければならない（MUST）。システム固有の部分は、型にせず JSON の値として返す（MUST）。
- **FR-004**: DB では、所有者・システム・キャラクター名・プレイヤー名・作成日時・更新日時・削除した日時など、一覧と検索と削除の判定に使う項目を通常の列にし、システム固有の部分を含むシート本体を JSON の列に保存しなければならない（MUST）。同じ値を列と JSON の両方に持たせて、ずれが起きるようにしてはならない（MUST NOT）。
- **FR-005**: 対象のシステムは、ゆうやけこやけとビギニングアイドルの 2 つとする（MUST）。システムは作成のときに決まり、後から変えられない（MUST）。
- **FR-006**: 共通の項目の入力は、次の規則で検証し、規則に合わない項目と直し方を返さなければならない（MUST）。
  - キャラクター名: 前後の空白を除いて 1〜100 文字。必須。
  - プレイヤー名: 0〜50 文字。
  - 年齢・性別: それぞれ 0〜20 文字の自由な文字列（「17 歳」「不明」などを入力できる）。
  - メモ: 0〜10,000 文字。改行を含めてよい。
- **FR-007**: システム固有の部分は、JSON のオブジェクトで、大きさに上限（256KB）がなければならない（MUST）。この機能では、オブジェクトであることと大きさだけを検証する。

#### 一覧と検索（ADR 0005: ログイン不要）

- **FR-008**: 誰でも（ログインせずに）シートの一覧（`/sheets`）を見られなければならない（MUST）。一覧には、削除されたシートを含めてはならない（MUST NOT）。
- **FR-009**: 一覧の各行には、キャラクター名・プレイヤー名・システム・所有者の表示名・更新日時を表示しなければならない（MUST）。
- **FR-010**: 一覧は、システム・キーワード・「自分のシートだけ」で絞り込めなければならない（MUST）。条件は組み合わせられる（MUST）。
  - システム: プルダウンで「すべて」（既定）と各システムから 1 つを選ぶ（MUST）。複数のシステムを同時に選ぶ形にはしない。
  - キーワード: キャラクター名またはプレイヤー名の部分一致。英字の大文字と小文字、全角と半角の違いを区別しない（MUST）。
  - 「自分のシートだけ」: ログインしているときだけ表示し、自分が所有者のシートに絞る（MUST）。ログインしていないときは、この条件を無視する（MUST）。
- **FR-011**: 一覧の並び順は、更新日時・作成日時・キャラクター名のそれぞれについて、順と逆の順を選べなければならない（MUST）。既定は更新日時の新しい順。項目ごとの最初の向きは、日時は新しい順、キャラクター名は名前の順。並び順の項目が同じシートの順も、毎回同じにする（MUST）。並び順を変えたら、最初のページに戻す（MUST）。キャラクター名の順の文字の並べ方は plan で決める。
  - 検索のフォームで、6 つの並び順から選べる（MUST）。
  - 表の形の一覧では、キャラクター名と更新日時の見出しを選んで並び替えられる（MUST）。並んでいない列の見出しを選ぶとその列の最初の向き、並んでいる列の見出しを選ぶと逆の向きにする。並んでいる列とその向きを、見た目と支援技術の両方に示す（MUST）。
- **FR-012**: 一覧は、1 ページに 20 件ずつ表示し、ページ番号で送れなければならない（MUST）。全体の件数またはページ数を表示する（MUST）。
- **FR-013**: 検索の条件・並び順・ページは URL に含め、URL を開けば同じ結果を表示しなければならない（MUST）。
- **FR-014**: 一覧と検索の応答時間は、シートの件数が増えても大きく延びてはならない（MUST NOT）。絞り込みと並べ替えに使う列で、絞り込みと並べ替えができるようにする。

#### 閲覧（ADR 0005: ログイン不要）

- **FR-015**: 誰でも（ログインせずに）シートの URL（`/sheets/<ID>`）を開いて、シートを見られなければならない（MUST）。URL にはシステムを含めず、ID だけで決まり、内容を変えても変わらないものにする（MUST）。
- **FR-016**: シートの画面の URL は、一覧 `/sheets`、閲覧 `/sheets/<ID>`、編集 `/sheets/<ID>/edit`、作成 `/sheets/new/<システム>` とする（MUST）。この機能で作るのは一覧と閲覧だけで、編集と作成の URL は各システムの Spec のために空けておく。
- **FR-017**: 閲覧画面には、共通の項目・システム・所有者の表示名・作成日時・更新日時を表示しなければならない（MUST）。システム固有の部分を表示する場所と、所有者の操作（編集・複製・削除）を置く場所を、各システムの Spec のために用意する（MUST）。
- **FR-018**: 存在しないシート・削除されたシート・形の正しくない ID を開いたときは、どの場合も同じように、シートが見つからないことを表示しなければならない（MUST）。削除されたことがわかる表示にしてはならない（MUST NOT）。
- **FR-019**: 所有者の情報として公開するのは、ユーザーの ID と表示名だけとし、ログイン ID をどの画面や API の応答にも含めてはならない（MUST NOT、002-auth の FR-034）。
- **FR-020**: 閲覧画面の題名には、キャラクター名とアプリ名を含めなければならない（MUST）。

#### 作成と複製（ADR 0005: ログインしたユーザー）

- **FR-021**: ログインしたユーザーは、API で、システムと共通の項目とシステム固有の部分を指定して、シートを作れなければならない（MUST）。作ったシートの所有者は、作ったユーザーにする（MUST）。所有者を作成の入力で指定できてはならない（MUST NOT）。
- **FR-022**: ログインしていない状態での作成は、API で拒否しなければならない（MUST）。
- **FR-023**: ログインしたユーザーは、API で、削除されていないどのシートでも複製できなければならない（MUST）。複製したシートは、元と同じシステム・共通の項目・システム固有の部分を持ち、所有者は複製したユーザー、作成日時と更新日時は複製した時刻にする（MUST）。キャラクター名の末尾には、複製であることがわかる文字を付ける（MUST）。付けた結果が上限を超えるときは、元のキャラクター名を上限に収まるよう短くする。
- **FR-024**: 複製したシートと元のシートは、互いに独立していなければならない（MUST）。片方の更新・削除が、もう片方に影響してはならない（MUST NOT）。
- **FR-025**: ログインしていない状態での複製は、API で拒否しなければならない（MUST）。

#### 更新と削除（ADR 0005: 所有者だけ）

- **FR-026**: シートの所有者は、API で、共通の項目とシステム固有の部分を更新できなければならない（MUST）。更新したら、更新日時を更新した時刻にする（MUST）。作成日時・所有者・システムは変えない（MUST）。
- **FR-027**: API は、更新と削除のたびに、ログインしているユーザーがそのシートの所有者であることを確かめなければならない（MUST）。所有者でないユーザー（管理者を含む）とログインしていない訪問者の更新・削除は拒否し、シートを変えてはならない（MUST NOT）。
- **FR-028**: 同じシートを別の場所で先に更新していたときは、古い内容をもとにした更新を受け付けず、先の更新の内容を守らなければならない（MUST）。他の場所で更新されたことを返す（MUST）。
- **FR-029**: シートの所有者は、API で、自分のシートを削除できなければならない（MUST）。削除したシートは、データを消さずに削除した日時を記録し、一覧・検索・閲覧・更新・複製・削除の対象から外す（MUST）。
- **FR-030**: 削除の取り消しの操作は、アプリの画面と API に用意してはならない（MUST NOT）。取り消しは、管理者が DB 操作で削除した日時を消して行う。取り消したシートは、削除前と同じ内容・同じ URL で戻る（MUST）。
- **FR-031**: 所有者を変える操作は、アプリの画面と API に用意してはならない（MUST NOT）。所有者の移動は、ADR 0005 のとおり DB 操作で行う（別の Spec で扱う）。

#### 関連データの取得（constitution V）

- **FR-032**: 一覧や閲覧で所有者の表示名を返すときは、表示するシートの件数にかかわらず、所有者の情報をまとめて取得しなければならない（MUST）。シート 1 件ごとに所有者を個別に問い合わせてはならない（MUST NOT）。

#### 画面

- **FR-033**: この機能では、一覧（検索を含む）の画面と、閲覧画面の共通部分だけを作らなければならない（MUST）。作成・編集の画面と、複製・削除の操作の画面（削除の確認を含む）は、各システムの Spec で作る。
- **FR-034**: ヘッダーの右端の操作の領域に、シートの一覧への入口を表示しなければならない（MUST）。トップページのシステムの一覧（「準備中」の表示を含む）は、この機能では変えない。
- **FR-035**: 画面は、UI 基盤（`001-ui-foundation`）の共通レイアウト・共通入力部品・テーマを使い、幅 360px の画面でも横スクロールを発生させてはならない（MUST NOT）。

### Key Entities

- **キャラクターシート**: 1 人のキャラクターの記録。ID、システム、所有者（ユーザー）、共通の項目（キャラクター名・プレイヤー名・年齢・性別・メモ）、システム固有の部分（JSON のオブジェクト）、作成日時、更新日時、削除した日時（削除していなければ空）を持つ。一覧と検索と削除の判定に使う項目は個別に持ち、システム固有の部分はまとめて持つ。所有者とシステムは作成のときに決まる（所有者だけは DB 操作で移せる）。
- **システム**: シートの書式を決めるゲームシステム。ゆうやけこやけとビギニングアイドルの 2 つ。システムごとに、シートの型（共通の項目を持つ）と、システム固有の部分の中身（各システムの Spec で決める）がある。
- **ユーザー（所有者）**: 002-auth で作ったユーザー。シートからは所有者として参照し、公開するのは ID と表示名だけ。プレイヤー名（シートの共通の項目、自由な文字列）とは別のもの。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ログインしていない訪問者が、一覧を開いてからキーワードで目当てのシートを見つけて開くまでを、30 秒以内にできる。
- **SC-002**: シートが 10,000 件あっても、どの絞り込みと並び順の組み合わせでも、一覧・検索・閲覧の結果が 1 秒以内に表示される。
- **SC-003**: 1 ページの表示件数を増やしても、所有者の表示名を取得するための DB への問い合わせの回数が増えない。
- **SC-004**: 所有者でないユーザー・管理者・ログインしていない訪問者による更新と削除の試みは、100% 拒否され、シートは 1 件も変わらない。
- **SC-005**: 一覧・閲覧の画面と API の応答に、所有者のログイン ID が含まれることが 0 件である。
- **SC-006**: 同じ条件の一覧の URL を別のブラウザで開くと、100% 同じ結果が表示される。ページを最後まで送ったとき、重複も抜けもない（一覧を見ている間にシートが更新されない場合）。
- **SC-007**: 同じシートを 2 か所から続けて保存したとき、先に保存した内容が黙って上書きされることが 0 件である。
- **SC-008**: 削除したシートが一覧・検索・閲覧に表示されることが 0 件であり、削除したシートのデータが DB から失われることも 0 件である。
- **SC-009**: 各システムの Spec が、共通の項目・保存・一覧・閲覧・権限の確認を作り直さずに、システム固有の部分の項目と画面を加えるだけでシステムを追加できる。

## Assumptions

- この機能の利用者は、ログインしていない訪問者と、002-auth で登録したユーザーである。管理者も、
  シートについては一般のユーザーと同じ権限を持つ（自分が所有者のシートだけを更新・削除できる）。
- 認証の仕組み（ログイン状態の判定）は 002-auth のものを使う。
- 画面は、UI 基盤（`001-ui-foundation`）の共通レイアウトと共通入力部品を使う。トップページの
  システムの一覧（「準備中」の表示を含む）は、各システムの Spec で作成画面ができたときに切り替える。
- システム固有の部分の項目・検証・画面、画像、ココフォリア出力、既存データの移行（旧 URL からの
  移動を含む）は、この機能に含めない。移行する既存シートは、ADR 0005 のとおり管理者の所有にし、
  作成日時と更新日時は移行の Spec で入れる。この機能の作成日時と更新日時は、作成・更新した時刻を
  自動で入れる。
- 作成の API は、システム固有の部分の中身を検証しない段階でも、ログインしたユーザーに公開する。
  利用者は招待されたコミュニティに限られ、作成画面への入口もまだないため、不正な中身のシートが
  作られる影響は小さいとみなす。各システムの Spec は、中身が空のオブジェクトのシートも扱える
  ようにする。
- 所有者を移す DB 操作と、削除の取り消しの DB 操作は、この機能ではコマンドにしない。必要に
  なったら、データ移行の Spec などで Taskfile のタスクにする。
- 削除したシートを一定の期間の後に完全に消す仕組みは、この機能に含めない。
- シートの削除を許すこと（所有者だけ、データは残す）は、ADR 0005 の「後続の Spec で決めること」の
  1 つに当たる。この機能の実装の中で、ADR 0005 に決定の内容を追記する。
- 旧アプリでは、一覧は新しい順、検索はキャラクター名とプレイヤー名の部分一致、ページは件数の指定で
  送っていた。
- シートの公開・非公開の切り替えはない。削除していないすべてのシートは誰でも見られる（ADR 0005）。
